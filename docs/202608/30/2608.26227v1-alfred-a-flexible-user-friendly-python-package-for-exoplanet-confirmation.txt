Alfred : A Flexible, User-Friendly Python Package for Exoplanet Confirmation 

Maxwell A. Kroft 1

> 1Department of Astronomy, University of Wisconsin–Madison, 475 N. Charter Street, Madison, WI, 53706, USA

ABSTRACT In the era of TESS, exoplanet follow-up and confirmation have become a massive community effort. With only about an eighth of the over 8,000 TESS exoplanet candidates confirmed, astronomers need flexible software to allow them to characterize many different kinds of systems with data from multiple telescopes and instruments. In this work, I present Alfred (the Awesome Library For Robust Exo-planet Detection), an open-source Python package for exoplanet detection and confirmation. Alfred 

is designed to be flexible and easy to use, allowing users to fit transit and radial velocity data for an arbitrary system of exoplanets. The code is released under an MIT license on GitHub  and is installable via pip, with documentation under active development.

DESCRIPTION OF Alfred Alfred wraps together all of the initialization, modeling, fitting, and output inherent in exoplanet transit and radial velocity (RV) fitting, streamlining the process for the user. It is built on the emcee (D. Foreman-Mackey et al. 2013) Markov chain Monte Carlo (MCMC) sampler, the batman (L. Kreidberg 2015) planetary transit model, and the isochrones (T. D. Morton 2015) stellar model interpolator, as well as a numerical solver for Kepler’s equation to model RVs. It also comes with precomputed quadratic limb darkening grids generated using ExoCTK (M. Bourque et al. 2021). Key features of Alfred v1.1, which is used for this publication, include: 

• Generalized transit and RV fitting for any number of planets in a system. Individual planets are not required to be detectable in every data set. 

• Simultaneous light curve detrending using the celerite2 (D. Foreman-Mackey et al. 2017; D. Foreman-Mackey 2018) damped harmonic oscillator Gaussian process kernel. 

• Optional simultaneous stellar parameter and SED fitting. 

• Simple transit timing variation fitting, treating each transit center time as a free parameter. 

• User-defined priors for any fit parameter, as well as the option to fix any parameter to a specific value. 

• Human-readable initialization files, each with a tailored GUI to help users set them up correctly. 

• Support for photometry from multiple instruments (with different limb darkening) or with different exposure times, as well as RVs from multiple instruments. 

• Automatic plot generation of MCMC chain distributions and best-fit models to the data. 

• The ability to load previous runs to remake plots or use raw chains.

USAGE EXAMPLES 

Alfred was designed with Python notebooks in mind, but can easily be run with standard scripts as well. Data, initialization files, and Alfred outputs are all stored in a directory specific to the exoplanet system, which the user can create with Alfred using built-in functions. Data and initialization parameters are read in via an ExoSystem object, which has class functions to run fits, generate plots, or perform other analyses. 

Alfred has been used two confirm exoplanets in two scientific papers so far: TOI-6054b and c (M. A. Kroft et al. 2025), which used a private, in-development version of the software, and GJ 523b (M. A. Kroft et al. 2026). Figure 1 shows an example RV fit for the TOI-6054 system performed with the current version of Alfred . This is a system with two eccentric sub-Neptunes, and I use the NEID data presented in the original publication (split into two RV eras defined by the NEID science team) as well as KPF data that has since become public. As this is an RV-only fit, Gaussian priors were placed on the period and time of conjunction for both planets, based off of the results of transit fitting. The plot shown is the default output from Alfred .

Alfred is available on GitHub  and is installable via pip under the name alfred-exoplanets . Documentation, including installation instructions, are available here. I am still actively developing the software and documentation, and plan to add many more features in the future. Questions, comments, and suggestions for the code are welcome and appreciated on the GitHub. Finally, I would like to thank Tayt Armitage for designing the Alfred logo.
